# 验证与飞牛实机验收

## 自动化与本机验证

- `pnpm --filter @fnos/dsh test`：全部通过，包括多用户租户、旧数据迁移、个人目录链接、Unix Socket 网关及原有回归测试。
- 两个模拟飞牛 UID 使用独立的用户所选工作目录 `HOME`、`.dsh`、状态文件、进程地址和运行版本；普通用户可启动与切换自己的实例，但不能进入管理页或调用全局版本接口。
- 空闲租户在超过设置的关闭时间后停止；HTTP/SSE/WebSocket 活跃连接会阻止关闭。管理员设置页可查看运行服务的空闲状态和预计关闭时间，并手动关闭指定服务。
- 模拟 HTTPS 外部域名与被改写的内部 Host：启动 URL、设置与重启跳转保持同源；默认不创建旧 TCP 监听。
- 登录用户、管理员、跨站和修改请求分层校验；飞牛 Cookie/Authorization/身份头隔离；每个租户使用自己的上游 Cookie。
- HTML/CSS URL、原样 JavaScript/JSON 与二进制请求；SSE 分块；WebSocket 来源校验、路径与双向数据。
- `pnpm run build dsh`：成功生成应用构建目录；移动样式覆盖安全区、窄屏底部操作面板、粗指针触控尺寸及减少动态效果偏好。
- 浏览器 API 的 VM 测试：Fetch Request 正文、动态脚本 URL、EventSource 与 WebSocket 地址。此项不等同于真实浏览器或 NAS 验收。

## 现有本机回归验证

- 配置校验；精确版本限制；不限量安装及手动删除；默认版本、用户已选版本和运行中版本删除保护；下载 integrity 失败不影响已有版本；标签错误隔离；切换失败恢复；并发互斥；市场安装幂等与失败重试。
- 首次安装自动获取 `latest` 并启动首个已完成工作目录授权的管理员租户；旧 profile 的依赖目录或 manifest 出现 `EACCES` 时，验证派生依赖重建、profile 备份、读取权限修复和最终重试。
- 真实 HTTP 服务测试：管理员权限、CSRF、端口冲突保留原配置、端口切换；任意插件路径与二进制 POST；SSE 首块即时到达；WebSocket 双向转发。
- 启动检查测试：DSH 启动令牌的 303 / Cookie 交换；实际子进程的启动、健康检查与停止。
- `fnpack` 1.2.3 实际打包，产物包含 manifest、入口、向导、生命周期脚本及应用负载。
- macOS 隔离目录安装真实 `@deepseek-ai/dsh@0.1.5-rc.1`（测试时 `latest`），自动安装市场并成功启动。
- 通过代理完成 DSH 认证首页访问，市场 `/dsh-market/status` 返回 200，`restart=false`；管理员一键重启后健康检查通过；查询 latest 成功。
- 浏览器验证：设置页展示真实运行状态；主入口在 DSH 就绪后会将同一应用框架切换到 DSH，跳过模型密钥设置后能进入设置中的插件市场。

测试没有使用或修改原有 DSH 用户数据，也没有配置模型 API Key 或执行模型任务。macOS 沙盒内的递归 fs.watch 会报 EMFILE；实际启动验证在沙盒外、独立测试目录、仅回环监听条件下完成。

## 仍需 fnOS 设备验收

当前没有连接飞牛 NAS，下列项目不能由 macOS 测试替代：

1. 在干净的 x86_64 和 arm64 **fnOS ≥ 1.2.0401** 上分别安装对应 `platform` 的 FPK，确认 `nodejs_v24` 依赖、`trim.file.userAccess` scope、应用用户权限及 Unix Socket 网关连接权限。
2. 首次安装后确认应用自动下载 `latest` 并设为默认版本；管理员完成工作目录授权后应自动启动自己的 DSH。模拟网络中断后从设置页重试。若原生依赖无预编译文件，确认系统构建工具链。
3. 准备至少两个普通飞牛账号。确认所有用户都能看到入口，普通用户会进入自己的 DSH，但直接访问设置页、下载版本、修改默认版本或 npm 源均返回 403。
4. 分别在管理员和两个普通账号中创建不同配置、会话、插件与工作区；重启应用后确认内容互不出现，且每个账号可独立选择已安装版本、重启自己的实例。
5. 同时打开多个账号，通过系统进程和监听信息确认每个已启动账号对应一个 DSH 子进程，均只监听随机回环端口；不需要也不应开放端口池。
6. 在桌面浏览器和飞牛 iOS/Android App ≥ 1.34.0 中验证状态岛。窄屏应显示安全区内的顶部状态、底部操作面板和不小于 40px 的触控目标；版本切换、重启、返回及错误提示均不能被系统栏遮挡。
7. 每个用户首次打开时，确认飞牛目录选择器仅显示“我的文件”，并在 `/volN/<uid>/` 下新建或选择 DSH 工作目录，例如 `dsh_home`；选择器应完成 ACL 授权。授权后 DSH 配置写入 `/volN/<uid>/dsh_home/.dsh`，工作区默认位于该目录。再从状态岛选择额外目录，确认后端 `trim.file.listUserAccess` 返回该 UID 的路径，`authorized/` 只出现额外目录链接；撤销授权后重新同步会移除旧链接。
8. 使用两个账号互相尝试访问对方工作目录及授权目录，记录 fnOS ACL 的实际结果；同时确认管理员授权自己的工作目录后，普通用户仍被拒绝访问该路径。
9. 从旧版升级，在旧共享 Home 或旧应用共享用户 Home 已有配置、插件、会话和工作区时，由对应用户完成工作目录选择；确认旧数据迁入该用户的 `/volN/<uid>/dsh_home`，其他用户得到空白 Home。
10. 安装至少 6 个实际版本，确认不会自动淘汰；删除未使用版本应成功，删除管理员默认版本、任一用户已选版本或正在运行的版本应被拒绝；切换兼容与不兼容版本验证恢复及错误显示。
11. 在应用中心停用、启用、升级和卸载，检查所有租户进程退出及飞牛数据保留规则；升级后确认各用户配置、插件和会话保留。
12. 测试需要的第三方插件，至少覆盖静态资源、普通 API、流式结果、WebSocket、安装、更新和卸载。宿主/插件 API 版本不兼容应明确报告，不能据代理测试宣称所有插件都兼容。
13. NAS 重启、DSH 异常退出、管理器异常退出、随机端口不可用、磁盘满等情况下检查状态和恢复。DSH 异常退出后状态岛应显示未运行，可以手动重启；当前没有无限自动重启循环。
14. 从外网通过 HTTPS 反向代理进入飞牛桌面和 App，仅转发飞牛 5666，确认 Network 中没有旧端口或根路径 `/api`、`/client` 请求，且 HTTPS/WSS、重定向、SSE 和资源 URL 正确。
15. 校验飞牛将浏览器 Origin 与内部 Host 分别转发时，HTTP 操作与 WebSocket 仍可用。重启管理器后通过入口重新打开再验证长连接。
16. 使用实际插件检查根路径原生动态 import、Service Worker、内联 HTML/CSS 或独立 Cookie 登录需求；发现兼容问题时记录失败 URL 与状态码，勿记录令牌、会话正文或完整请求头。
17. 浏览器扩展的 `userscript.html` CSP 提示应与应用请求失败区分；必要时在禁用扩展的窗口复测，不通过放宽应用 CSP 来处理扩展注入。
18. 在带有旧 `.dsh/profiles/web` 目录、旧依赖树或受限 profile manifest 的升级环境中启动市场安装；确认仅派生依赖或 profile 被恢复，工作区、会话和备份目录未丢失，并确认修复后的新 profile 可被 DSH web worker 读取。
