# 验证与飞牛实机验收

## 子路径网关本机验证

- `pnpm test`：34 项通过，包括原有回归测试及新的 Unix Socket 网关测试。
- 模拟 HTTPS 外部域名与被改写的内部 Host：启动 URL、设置与重启跳转保持同源；默认不创建旧 TCP 监听。
- 管理员、跨站和修改请求校验；飞牛 Cookie/Authorization/身份头隔离；上游 Cookie 不下发。
- HTML/CSS URL、原样 JavaScript/JSON 与二进制请求；SSE 分块；WebSocket 来源校验、路径与双向数据。
- 浏览器 API 的 VM 测试：Fetch Request 正文、动态脚本 URL、EventSource 与 WebSocket 地址。此项不等同于真实浏览器或 NAS 验收。

## 现有本机回归验证

- `pnpm test`：配置校验；精确版本限制；最多 5 个版本且保护当前版本；下载 integrity 失败不淘汰旧版本；标签错误隔离；切换失败恢复；并发互斥；市场安装幂等与失败重试。
- 真实 HTTP 服务测试：管理员权限、CSRF、端口冲突保留原配置、端口切换；任意插件路径与二进制 POST；SSE 首块即时到达；WebSocket 双向转发。
- 启动检查测试：DSH 启动令牌的 303 / Cookie 交换；实际子进程的启动、健康检查与停止。
- `fnpack` 1.2.3 实际打包，产物包含 manifest、入口、向导、生命周期脚本及应用负载。
- macOS 隔离目录安装真实 `@deepseek-ai/dsh@0.1.5-rc.1`（测试时 `latest`），自动安装市场并成功启动。
- 通过代理完成 DSH 认证首页访问，市场 `/dsh-market/status` 返回 200，`restart=false`；管理员一键重启后健康检查通过；查询 latest 成功。
- 浏览器验证：设置页展示真实运行状态；主入口在 DSH 就绪后会将同一应用框架切换到 DSH，跳过模型密钥设置后能进入设置中的插件市场。

测试没有使用或修改原有 DSH 用户数据，也没有配置模型 API Key 或执行模型任务。macOS 沙盒内的递归 fs.watch 会报 EMFILE；实际启动验证在沙盒外、独立测试目录、仅回环监听条件下完成。

## 仍需 fnOS 设备验收

当前没有连接飞牛 NAS，下列项目不能由 macOS 测试替代：

1. 在干净的 x86_64 和 arm64 fnOS ≥ 1.1.3100 上分别安装对应 `platform` 的 FPK，确认 `nodejs_v24` 依赖安装、应用用户权限及 Unix Socket 网关连接权限。
2. 首次安装无需选择端口，打开主入口确认会自动进入设置页；下载 latest、安装市场；模拟网络中断并从设置页重试。若原生依赖无预编译文件，确认系统构建工具链。
3. NAS 管理员可以访问设置页并从同一应用窗口打开 DSH；普通账号、匿名网关请求、跨站 POST 和未认证 WebSocket 均被拒绝。
4. 安装 6 个实际版本，确认完成安装后最多保留 5 个且当前版本未被清理；切换兼容与不兼容版本验证恢复及错误显示。
5. 在应用中心停用、启用、升级和卸载，检查进程退出及飞牛数据保留规则；升级后确认原配置、插件、会话保留。
6. 测试需要的第三方插件，至少覆盖静态资源、普通 API、流式结果、WebSocket、安装、更新和卸载。宿主/插件 API 版本不兼容应明确报告，不能据代理测试宣称所有插件都兼容。
7. NAS 重启、DSH 异常退出、管理器异常退出、端口占用、磁盘满等情况下检查状态和恢复。DSH 异常退出后设置页应显示未运行，可以手动重启；首版没有无限自动重启循环。
8. 从外网通过 HTTPS 反向代理进入飞牛桌面，仅转发飞牛 5666、不开放 3080，打开 DSH 并确认 Network 中没有请求旧端口或根路径 `/api`、`/client`。服务端确认没有旧端口监听。
9. 在上述环境测试首次加载、页面刷新、设置往返、重启 DSH、流式对话和插件市场安装/更新；确认 HTTPS/WSS、自定义外部端口、重定向和资源 URL 均正确。
10. 校验飞牛将浏览器 Origin 与内部 Host 分别转发时，HTTP 操作与 WebSocket 仍可用。重启管理器后通过桌面入口重新打开再验证长连接。
11. 使用实际插件检查根路径原生动态 import、Service Worker、内联 HTML/CSS 或独立 Cookie 登录需求；发现兼容问题时记录失败 URL 与状态码，勿记录令牌、会话正文或完整请求头。
12. 浏览器扩展的 `userscript.html` CSP 提示应与应用请求失败区分；必要时在禁用扩展的窗口复测，不通过放宽应用 CSP 来处理扩展注入。
