# 架构

- `cmd/main` 启停 Node 管理进程；Node 在 `@appdata` 保存运行状态与受校验的执行副本；主配置、站点、版本文件、日志及 Nginx 请求处理临时目录位于 `@appshare`。应用版本与 Nginx 二进制版本分开保存。
- 管理页通过 fnOS 网关 Unix socket 访问，仅管理员可读写。写接口要求 JSON 及自定义请求头；请求参数不拼接 shell 命令。
- 站点文件按文件名管理，顶层限定为 `server` 块。禁用时将 `name.conf` 改名为 `name.conf.disabled`，使受管 `*.conf` 引用跳过该文件；重新启用前将它加入候选目录校验，成功后再改名并重载，失败时回滚文件状态。禁用站点仍可编辑和删除。候选目录使用当前主配置替换站点 include 路径后验证整套配置，验证通过后替换正式文件并向 Nginx 主进程发送 HUP。主配置编辑也先验证候选文件和现有站点，保留受管站点 include 行；验证失败不覆盖原文件，重载失败则恢复原文件。
- 证书通知是单个文本文件，hook 原子替换其中的事件标识。应用定时读取，与上次成功处理的标识比较；测试前缀忽略。
- Nginx 版本从 nginx.org 官方 Debian/Ubuntu 仓库检查，按发行版代号和架构选择 `.deb`，核对下载大小及 SHA256，使用 `dpkg-deb -x` 在应用数据目录临时提取二进制，持久版本放在应用共享目录，并以私有哈希记录校验后复制为执行副本；安装后运行 `-v`/`-V` 检查可执行性。没有当前版本时，首次下载完成后复用版本启用流程自动启动；失败时保留下载结果并反馈原因。已有当前版本时只下载，不自动替换；手动启用时允许服务短暂停止，失败时尝试恢复旧版本。

应用采用 `run-as=package`。管理服务与 Nginx master/worker 均以 `nginx_for_fnos` 运行，直接监听的 TCP 端口应为 1024–65535。管理 Unix Socket 使用 0660 权限，经统一网关提供管理员访问；同 UID 的 Nginx worker 也能连接此 Socket，因此它不是 worker 与管理服务之间的隔离边界。管理员鉴权依赖 fnOS 网关注入的身份头及 Socket 的本地访问控制，须在实机检查 Socket 所有者、组和网关访问权限。证书文件、站点目录及通知文件由用户授权给应用账户。旧版 root 所有的数据可能阻止包用户启动或迁移，不能由应用自行提权修复。

- 首次升级迁移旧 `@appdata` 的配置、站点、版本与日志；同名目标不覆盖。主配置仅在不存在时生成，后续保留手工修改，并在迁移时更新旧目录路径、移除旧版生成的 `user` 指令、补齐缺少的五类 HTTP 临时目录设置。校验前会创建应用用户可写的临时目录。所有 Nginx 启动与校验命令使用 `-e` 指定应用共享目录的初始错误日志。
