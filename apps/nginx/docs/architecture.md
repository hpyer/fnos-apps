# 架构

- `cmd/main` 启停 Node 管理进程；Node 在 `@appdata` 保存运行状态与受校验的执行副本；主配置、站点、版本文件、日志及 Nginx 请求处理临时目录位于 `@appshare`。应用版本与 Nginx 二进制版本分开保存。
- 管理页通过 fnOS 网关 Unix socket 访问，仅管理员可读写。写接口要求 JSON 及自定义请求头；请求参数不拼接 shell 命令。
- 站点文件按文件名管理，顶层限定为 `server` 块。候选目录使用当前主配置替换站点 include 路径后验证整套配置，验证通过后替换正式文件并向 Nginx 主进程发送 HUP。主配置编辑也先验证候选文件和现有站点，保留受管站点 include 行；验证失败不覆盖原文件，重载失败则恢复原文件。
- 证书通知是单个文本文件，hook 原子替换其中的事件标识。应用定时读取，与上次成功处理的标识比较；测试前缀忽略。
- Nginx 版本从 nginx.org 官方 Debian/Ubuntu 仓库检查，按发行版代号和架构选择 `.deb`，核对下载大小及 SHA256，使用 `dpkg-deb -x` 在应用数据目录临时提取二进制，持久版本放在应用共享目录，并以私有哈希记录校验后复制为执行副本；安装后运行 `-v`/`-V` 检查可执行性。切换时允许服务短暂停止，失败时尝试恢复旧版本。

当前版本使用 root 模式，管理服务也以 root 运行。Nginx worker 以应用包用户运行，以应用设置授予的权限读取站点目录；管理 Unix Socket 使用 root 专用权限，避免 worker 连接并伪造网关身份。fnOS 对第三方 root 应用的安装支持和网关连接 root 专用 Socket 的能力需要实机确认。后续可将管理服务与仅负责 Nginx 进程及端口的特权组件拆开。

- 首次升级迁移旧 `@appdata` 的配置、站点、版本与日志；同名目标不覆盖。主配置仅在不存在时生成，后续保留手工修改，并在迁移时更新旧目录路径和 worker 主组、补齐缺少的五类 HTTP 临时目录设置。校验前会创建并设置 worker 可写的临时目录。所有 Nginx 启动与校验命令使用 `-e` 指定应用共享目录的初始错误日志。
