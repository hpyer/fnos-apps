# fnOS 实机验收

以下项目必须在目标 fnOS 版本和 x86_64/arm64 设备上分别验证，本机 `pnpm test` 不能替代。

1. 包用户权限 FPK 可安装；Node 管理进程和 Nginx master/worker 均以 `nginx_for_fnos` 运行；检查管理 Unix Socket 的所有者、组与 0660 权限，统一网关可访问且非管理员不可访问。
2. 从官方稳定版和主线版仓库检查、下载、校验、提取当前架构的 Nginx ELF。授权 `/vol1/1000/` 下的测试站点目录后确认静态文件可读取，验证 1024 和 8080 等高端口可监听、80/443 不可直接监听，以及进程退出清理。
3. 导入原有各 `server` 配置，检查已映射的上游端口、证书/私钥路径和读权限。
4. 输入无效配置时，正式配置与正在运行的服务保持原状；有效配置保存后检查请求及 WebSocket 连接。禁用站点后确认该站点不再提供服务、列表置灰且排在启用站点后；编辑禁用站点后重新启用，确认校验失败时保持禁用、成功后恢复服务。
5. 在证书容器续期成功后写通知标识，检查间隔、重载、失败保留、应用停止期间更新和测试文件忽略行为。
6. 切换 Nginx 版本，验证成功启动与失败回退；确认动态库、模块和配置兼容。
7. 从旧包升级前备份数据，检查旧版 root 所有的应用安装目录（需创建管理 Socket）、`@appdata`、`@appshare` 及其文件能否由应用用户读写；无法访问时先由管理员迁移文件权限。升级后确认主配置、站点、版本和日志迁到 `@appshare`，旧版生成的 `user` 指令已移除，旧版本可切换；将原有低端口站点改为高端口。通过弹窗编辑主配置并保存，确认无效配置不会覆盖原文件、有效配置会平滑重载且重启应用后保留，保存站点时该配置参与校验。确认旧主配置自动补齐 HTTP 临时目录设置，新增站点不再因 `/var/cache/nginx/client_temp` 缺失而失败。
8. 清理共享目录中的日志后再验证日志写入；修改已下载的二进制文件时，应用应拒绝切换或启动。
9. 重启或升级原生应用后，检查站点文件、通知设置、已安装 Nginx 版本及启动状态。
