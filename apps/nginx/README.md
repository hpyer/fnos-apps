# Nginx for fnOS

fnOS 原生 Nginx 反向代理管理应用。管理页通过飞牛统一网关访问，支持独立的 `server` 配置文件、全文编辑、保存前 `nginx -t`、平滑重载、Nginx 官方版本检查、下载与启用，以及证书更新通知文件。

管理页也会检查本应用的 GitHub Release；有新版本时常驻提示对应架构 FPK 的下载链接，安装仍在飞牛应用中心手动完成。此提示与页面中的 Nginx 官方版本检查相互独立。

## 使用方式

1. 安装应用后，在管理页选择稳定版（默认）或主线版，检查 nginx.org 官方仓库中的最新版本，点击「下载并安装」。首次下载安装完成后，应用会自动启用并启动该版本；如果启动失败，下载的版本仍会保留，并显示失败原因。应用根据 `/etc/os-release` 和设备架构匹配 Debian/Ubuntu 官方软件包，只下载官方 HTTPS 地址并核对仓库给出的大小与 SHA256；不修改系统软件源，也不运行软件包的安装脚本。系统不在支持名单、缺少 `dpkg-deb`、动态库不兼容或官方仓库不可达时会显示错误，需在目标 NAS 上确认。应用包不内置 Nginx。
2. 已有当前版本时，新下载的版本不会自动替换它；在「已安装版本」中点击「启用」才会停止旧进程并启动新版本。启动失败时应用尝试恢复原版本。顶部左侧根据运行状态显示「启动」或「停止」，运行中还可点击「重启」；停止和重启须先确认。右侧「校验并重载配置」会先校验再平滑重载。
3. 「站点配置」面板右上角可编辑主配置，或新增站点。应用以非 root 的 `nginx_for_fnos` 用户运行，显式指定的 TCP `listen` 端口须为 1024–65535；省略 `listen` 时 Nginx 默认监听 8000。新建站点时只输入文件主名，应用自动补上 `.conf`；在文本编辑器中写入一个或多个 `server {}` 块。每个站点可临时禁用或重新启用；禁用项置灰并排在列表末尾，仍可编辑或删除。Nginx 主配置位于 `/vol1/@appshare/nginx-for-fnos/nginx.conf`（实际卷号按安装位置确定），站点位于同目录的 `sites/`，已下载版本位于 `versions/`，Nginx 与管理服务日志位于 `logs/`，请求处理临时文件位于 `temp/`。主配置只在首次启动时生成，之后保留手工改动；编辑主配置或站点时都先用候选文件运行 `nginx -t`，通过后才写入正式文件，运行中的 Nginx 会平滑重载。保存和重新启用站点前须已安装并选择 Nginx 版本，以便执行校验；主配置须保留应用生成的站点 `include` 行。
4. 证书更新通知默认关闭。启用后填写 NAS 上的通知文件绝对路径及检查间隔，默认 30 分钟。点击「测试并创建文件」会以应用身份创建或检查文件。证书服务更新成功后向此文件写入新的时间戳标识，应用发现新内容后校验并重载。

证书服务位于 Docker 容器时，需要把通知文件所在目录映射到容器。容器中的路径可以与 NAS 路径不同；应用配置填写 **NAS 路径**。成功 hook 的 POSIX shell 示例（容器内映射路径为 `/notify`）：

```sh
printf '%s-%s\n' "$(date -u '+%Y%m%dT%H%M%SZ')" "$$" > "/notify/nginx.reload.$$" &&
mv -f "/notify/nginx.reload.$$" "/notify/nginx.reload"
```

文件中的时间戳是通知标识，不用作系统时钟校准。应用在 `@appdata/nginx-for-fnos` 记录上次成功处理的标识和实际处理时间，管理页仅显示处理时间；失败时保留待处理状态。测试文件由应用写入的 `test:` 内容不会触发重载。多个站点共用一张通配符证书时只需一次通知，整套 Nginx 配置一起重载。

## 构建与验证

```sh
pnpm test
pnpm run build nginx
pnpm run pack nginx --arch x86
```

应用包、Node 管理服务及 Nginx master/worker 均以 `nginx_for_fnos` 运行，不申请 root 权限。Linux 默认不允许此用户直接绑定 1024 以下端口；如需对外使用 80/443，请在路由器或已有入口将流量转发至应用监听的高端口。证书、站点和通知文件也须授予应用用户相应的读写权限。管理 Unix Socket 仅开放给应用用户和同组进程，管理接口只接受经飞牛统一网关鉴权的管理员请求。统一网关连接、Nginx 二进制依赖、证书文件权限、高端口占用和原有 WebSocket 连接行为，均须在目标 fnOS 版本及架构上实机验收；本机测试和打包不构成 NAS 验收。

升级旧包时会将原先位于 `@appdata/nginx-for-fnos` 的主配置、站点、版本和 Nginx 日志迁到 `@appshare/nginx-for-fnos`，遇到同名文件会保留共享目录中的文件及旧文件，避免覆盖。已有主配置会移除旧版生成的 `user` 指令并补上缺少的请求处理临时目录设置；应用会在校验前创建这些目录。状态、临时候选配置及受校验的执行副本仍放在 `@appdata`；共享目录中的版本文件被改动后不能直接执行，需重新从官方下载安装。若从 root 权限版升级，先备份数据，并在 NAS 上确认应用安装目录（管理 Socket 所在位置）、`@appdata`、`@appshare` 及其现有文件可由 `nginx_for_fnos` 读写；旧版 root 所有且不允许应用用户访问的文件无法由新版自动修复权限。原有低端口站点配置须改成高端口。`nginx -t` 只校验配置，低端口绑定失败可能到启动或重载时才出现。手工清理日志时请保留 `logs/` 目录本身。

尚未提供动态模块打包、证书自动申请或续期。官方软件包的索引通过 HTTPS 获取，下载的 `.deb` 与该索引中的 SHA256 对照；当前版本尚未校验仓库 GPG 签名。配置文件中的上游地址应使用 NAS 可访问的已映射端口，不能直接依赖 Docker 网络内部的容器名。
