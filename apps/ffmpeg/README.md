# FFmpeg for fnOS

fnOS 原生命令行工具与版本管理应用。默认提供全局 `ffmpeg`，可选安装媒体信息查询工具 `ffprobe`。由管理员下载、校验、启用、回滚和删除 FFmpeg 构建。FPK 不内置 FFmpeg，按 NAS 的 x86_64 或 ARM64 架构下载。

## 使用

1. 安装对应架构的 FPK，应用依赖飞牛 Node.js 24。管理服务以专用 `ffmpeg_for_fnos` 包用户运行，页面通过统一网关仅向管理员开放。
2. 打开管理页，点击「检查版本」，选择稳定版，点击「下载并安装」。NAS 需能访问 `ffmpeg.martin-riedl.de`。默认只下载独立的 ffmpeg ZIP，不下载 ffprobe；网络失败、校验失败或不兼容会显示原因。
3. 下载只安装文件，不切换当前版本。在「已安装版本」中点击「启用」后，全局命令才可使用；首次安装也需要手动启用。
4. 切换到另一个版本后，可通过「回滚」恢复，或在列表中启用任意已安装版本。下载或自检失败不会改动当前指针，启用失败不会替换当前版本。当前指针是启用状态的唯一依据。
5. 如需 ffprobe，勾选「同时安装 ffprobe」。当前已启用版本缺少该工具时，先下载同一固定构建的 ffprobe，通过校验和自检后补装，再保存同步选项；失败不改变选项和当前 ffmpeg。没有启用版本时直接保存选项。随后安装的新版本会同时下载两个组件；切换或回滚到缺少 ffprobe 的历史版本时，也会先补齐再切换。
6. 取消勾选只停止后续同步，保留已安装的 ffprobe；已有工具仍可调用。旧 BtbN 构建和已安装版本保留，无需重新下载已具备的组件。
7. 「构建信息」显示版本、编译参数、编码器和编译支持的硬件加速接口，该列表不代表已经验证目标设备上的硬件转码。命令路径默认折叠，可展开复制。下载期间在安装区显示进度，操作结果使用公共 Toast 提示；错误结果保留至手动关闭，状态轮询不会重复弹出。

```sh
ffmpeg -version
/usr/local/bin/ffmpeg -version
# 勾选安装 ffprobe 后
ffprobe -version
```

终端的 PATH 需要包含 `/usr/local/bin`。定时任务和其他原生应用建议使用上述绝对路径；应用若内置另一套 FFmpeg，需要该应用支持配置命令路径。Docker 容器不会自动获得宿主机命令。

fnOS 资源配置会注册两条轻量入口脚本；未安装 ffprobe 二进制时，其入口只显示安装提示并返回 127。管理页会标注「当前版本未安装」，不将入口已注册当作组件可用。

全局命令在调用者的账户下直接执行，继承标准输入、参数、信号和退出码，不经过 Web 管理服务，不提权。媒体文件权限和 GPU 设备权限由调用者自身的账户及系统授权决定；管理账户不会自动给其他账户授予权限。

## 版本来源与兼容性

- 默认来源为 [Martin Riedl FFmpeg Builds](https://ffmpeg.martin-riedl.de/) 的 Linux x86_64 / ARM64 独立稳定版组件，不是 FFmpeg 官方发布的二进制。默认不列出开发快照，不接受用户上传或任意 URL。
- 同一版本按固定时间戳目录绑定 ffmpeg 与 ffprobe，不使用会变化的 latest 下载地址。成功查询缓存一分钟，仅查询 ffmpeg 的校验和与大小；未勾选时不请求 ffprobe 文件。每个 ZIP 必须通过上游 SHA256 和大小校验，重定向逐跳限制为同一 HTTPS 来源。校验依赖同一上游的元数据，没有额外验证独立签名。
- 独立下载减少了不需要的工具，但 ffmpeg 本身仍包含多种编解码器。下载量随上游构建变化；启用 ffprobe 后需额外下载大小接近的独立 ZIP。页面显示的 ffmpeg 大小不等于双组件总量，解压后占用也大于下载量。
- 下载连接中断会最多自动重试 3 次，页面显示重试进度。同一操作内优先按 HTTP Range 续传，并用 ETag 或修改时间（上游提供时）限制文件版本；服务器返回完整文件或拒绝续传时清空残片重下。续传仍须通过整份 SHA256、文件大小及解压校验。每个文件总下载时间最多 30 分钟，连接长时间无响应会触发重试。最终失败、取消或服务重启会清理暂存，重新点击下载时从头开始，不跨操作保留残片。
- 下载后校验 ELF 架构，运行 `-version`，生成 0.05 秒 PCM 音频并解码验证；已安装 ffprobe 时还检查两组件版本一致，并用 ffprobe 确认输出。这不能替代实际视频任务和 GPU 验收。动态链接、glibc、CPU 指令集、驱动及具体编码器兼容性须在目标 NAS 上确认。
- ZIP 解压由内置 Node 实现，只接受一个与组件名一致的常规文件，检查 CRC、展开大小、目录与数据边界，拒绝加密、符号链接和路径穿越。系统 `/usr/bin/flock` 用于任务锁，`/usr/bin/xz` 用于兼容旧 BtbN 归档；安装和升级检查工具存在，不安装或替换系统软件包。
- 已安装的 [BtbN 构建](https://github.com/BtbN/FFmpeg-Builds) 继续支持启用、回滚和删除。若需补装缺失的 ffprobe，按原始构建记录下载归档，仅提取所需工具及许可证；该兼容路径仍需访问 GitHub Release/CDN，下载量也仍是整份旧归档。
- 每个版本保存构建来源、组件 URL 与 SHA256；BtbN 归档保留 LICENSE.txt，独立组件保留 SOURCE.txt。上游构建的编译选项及第三方库许可证以具体构建为准；独立组件来源包含 nonfree 选项，不能按一个通用 GPL 标签概括。如另行分发二进制，应核对其依赖、源码和声明要求；本项目 FPK 不包含这些二进制。

## 数据与任务

版本保存在 `${TRIM_PKGVAR}/versions`，未完成下载位于私有 `staging` 目录，`current` 为相对版本软链接，`previous.json` 保存上一版本，`settings.json` 保存 ffprobe 同步选项。补装只添加当前构建的 ffprobe 与组件元数据，不替换 ffmpeg 或当前指针；中断后的组件提交日志在下次启动时校验恢复。管理状态和日志不放入用户共享目录；版本文件允许其他账户读取执行，只允许应用账户修改。通过 `/var/apps/ffmpeg-for-fnos/var` 可访问稳定的运行数据路径。不要手工编辑这些文件。

全局入口先取得目录锁并读取当前版本，再取得该版本的共享锁；执行前释放目录锁，版本锁随 exec 保留。因此切换不等待已有长任务，旧任务仍运行原版本。删除使用排他锁，拒绝删除当前版本和仍被全局入口调用的版本。

固定版本路径为 `/var/apps/ffmpeg-for-fnos/var/versions/<构建标识>/bin/ffmpeg`，可用于需要锁定版本的调用。但**直接调用版本路径会绕过全局入口的任务锁**，使用者须自行保证任务结束后再删除该版本。不可仅根据系统进程名称批量结束 FFmpeg。

设计上，停止管理服务不结束从终端或其他应用启动的 FFmpeg；管理服务升级也不主动切换 FFmpeg。fnOS 停止时是否保留资源链接、升级和卸载的链接清理顺序、数据保留行为须实机验证。卸载前先结束相关命令并备份需要保留的版本。上游有历史资产保留期限，本地已安装版本不依赖上游即可回滚，但删除后不保证还能重新下载同一构建。

安装和升级遇到 `/usr/local/bin/ffmpeg` 或 `/usr/local/bin/ffprobe` 已被其他来源占用时会报冲突。应用不会改写 `/usr/bin`、系统 PATH、软件源或系统 FFmpeg；如果 PATH 中更靠前的位置已有同名命令，应明确使用本应用的绝对路径。

## 开发与验证

```sh
pnpm install
pnpm run dev ffmpeg
pnpm test
pnpm run build ffmpeg
pnpm run pack ffmpeg --all
```

本机预览地址为 `http://127.0.0.1:3084/app/ffmpeg-for-fnos/`；macOS 上只预览管理页，不下载或启用 Linux 构建。双架构管理包不含原生 Node 扩展，不需要分别编译 FFmpeg。公共版本检查器及 toast 的代码和样式会随 FPK 打包，不依赖安装后的 workspace。

见 [架构](docs/architecture.md) 和 [验收清单](docs/acceptance.md)。本机测试和 FPK 打包成功不代表 fnOS 实机验收通过。
